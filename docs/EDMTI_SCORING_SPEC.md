# EDMTI 计分逻辑与题库落地方案

> Status: Proposed
> Last Updated: 2026-06-09
> Scope: EDMTI 正式题库、隐藏人格触发、结果映射、后台初始化数据口径

---

## 1. 目标

这份方案要同时满足 6 个目标：

1. 保留 `EDMTI` 世界观。
2. 保留 `16` 个常规人格 + `4` 个隐藏人格。
3. 保留固定第 `17` 题彩蛋题。
4. 最终对外展示的是 `BOMB / SUNNY / GLIT` 这类人格名，而不是直接展示 `ENFJ / INTP`。
5. 隐藏人格由特定答案直接触发，并无视常规题结果。
6. 保留“每题四个选项分别对应不同轴”的题面风格，但修复原始计分模型的数学不自洽问题。

---

## 2. 核心数学逻辑

### 2.1 不再直接累加 8 个原始轴分，而是改为 4 组“隐藏平衡值”

内部维护 4 个隐藏 pair balance：

- `balanceEI`
- `balanceSN`
- `balanceTF`
- `balanceJP`

初始值全部为 `0`。

含义如下：

- `balanceEI > 0`：偏 `E`
- `balanceEI < 0`：偏 `I`
- `balanceSN > 0`：偏 `S`
- `balanceSN < 0`：偏 `N`
- `balanceTF > 0`：偏 `T`
- `balanceTF < 0`：偏 `F`
- `balanceJP > 0`：偏 `J`
- `balanceJP < 0`：偏 `P`

### 2.2 每个选项采用“主权重 + 次权重”的商业化结构

每个选项最多影响两个维度组：

- 一个主维度：`±2`
- 一个次维度：`±1`

这样做有 4 个好处：

1. 保留了“每个选项代表一个不同人格倾向”的文案风格。
2. 不会再出现“16 题却很难把单轴堆到 >=9”的问题。
3. 不会再大量出现多个维度同时难以区分的问题。
4. 允许你想要的那种“选了 E 强倾向，同时顺手削弱另一个风格”的效果，但仍然可解释。

### 2.3 隐藏 8 轴分数改为由 4 组 balance 推导

常规题作答结束后，内部推导隐藏 8 轴展示分数：

- `E = clamp(8 + balanceEI, 0, 16)`
- `I = clamp(8 - balanceEI, 0, 16)`
- `S = clamp(8 + balanceSN, 0, 16)`
- `N = clamp(8 - balanceSN, 0, 16)`
- `T = clamp(8 + balanceTF, 0, 16)`
- `F = clamp(8 - balanceTF, 0, 16)`
- `J = clamp(8 + balanceJP, 0, 16)`
- `P = clamp(8 - balanceJP, 0, 16)`

这样有两个关键优势：

1. 你原先想保留的“`>= 9` 表示偏向该侧，`<= 8` 表示对立侧”仍然成立。
2. `HHHH` 的“所有维度都在 `7-9` 之间”也重新变得数学上成立。

### 2.4 HHHH 的数学定义

`HHHH` 触发条件定义为：

- `abs(balanceEI) <= 1`
- `abs(balanceSN) <= 1`
- `abs(balanceTF) <= 1`
- `abs(balanceJP) <= 1`

等价于：

- `E/I`
- `S/N`
- `T/F`
- `J/P`

四组推导分都落在 `7-9` 之间。

## 3. 最终判定顺序

### 3.1 隐藏人格优先级

最终结果按以下顺序判定：

1. `PHOENIX`
2. `CPDD`
3. `DRUNK`
4. `HHHH`
5. 常规 16 人格

### 3.2 隐藏人格直接触发规则

- `PHOENIX`
  - 第 `7` 题选凤凰专属选项，直接触发
- `CPDD`
  - 第 `17` 题选 `CPDD` 选项，直接触发
- `DRUNK`
  - 第 `17` 题选“必须喝到断片”，直接触发
- `HHHH`
  - 未触发以上 3 个 direct trigger，且 4 组 balance 全部在 `[-1, 1]`

### 3.3 第 17 题的定位

第 `17` 题定义为“隐藏人格触发题”，不是常规四维计分题。

- 选 `C`：`DRUNK`
- 选 `D`：`CPDD`
- 选 `A/B`：不参与常规 4 组 balance 计分

这样可以保持：

- 正式主人格仍由前 `16` 道常规题决定
- 彩蛋题只负责隐藏人格
- 逻辑清楚，便于运营解释

### 4.3 常规人格的计算规则

先得到四组结果字母：

- `EI`
- `SN`
- `TF`
- `JP`

然后拼成 `mbtiCode`，再映射为展示人格。

#### 单组字母判定规则

- 若 `balance > 0`，取左侧字母
- 若 `balance < 0`，取右侧字母
- 若 `balance = 0`，进入 tie-break

#### tie-break 顺序

1. 比较该组的“主命中次数”
2. 若仍相同，比较该组“次权重累计值”
3. 若仍完全相同，采用固定兜底：
   - `EI` 平票取 `I`
   - `SN` 平票取 `N`
   - `TF` 平票取 `F`
   - `JP` 平票取 `P`

这套兜底只会在极少数边界用户出现，而且 `HHHH` 已经先拦截掉最平均的用户了。

## 5. 计分字段建议

每个选项落库时建议维护：

- `primaryPair`
- `primaryDelta`
- `secondaryPair`
- `secondaryDelta`
- `directResultCode`

其中：

- `primaryDelta` 只能是 `+2` 或 `-2`
- `secondaryDelta` 只能是 `+1` 或 `-1`
- `directResultCode` 仅隐藏触发项使用

如果现有表结构只支持 `scorePayload`，可转为：

```json
{
  "balanceEI": 2,
  "balanceSN": -1
}
```

或：

```json
{
  "EI": 2,
  "SN": -1
}
```

都可以。

## 10. 实现建议

服务端建议改为两段式计算：

1. 先扫描 direct trigger
2. 再计算四组 balance
3. 由四组 balance 推导 8 轴隐藏分
4. 由四组胜负拼出 `mbtiCode`
5. 再由 `mbtiCode` 查询常规 result type

推荐查询方式：

- 隐藏人格：按 `code` 查
- 常规人格：按 `mbtiCode` 查

这样可以保证：

- 你对外显示的是人格展示名
- 内部保留 EDMTI 四维结构
- 后台运营也能同时管理“显示人格”和“内部映射”
