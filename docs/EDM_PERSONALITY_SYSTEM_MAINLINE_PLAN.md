## 当前目标

建设一套新的 `EDM Personality / 电子音乐人格` 系统：

- iOS 个人主页快捷入口新增 `MBTI`
- 用户通过一组题目完成电子音乐人格测试
- 答题体验整体复用现有 quiz UI 风格
- 与现有 quiz 的关键差异：
  - 不计时
  - 支持 `上一步`
  - 支持 `下一步`
  - 支持 `放弃`
  - 结果不是“通过/失败”，而是“人格结果”
- 普通用户只能正式完成一次
- admin/debug 身份在开始页可进入 `调试模式`
- Web 端需要有对应的后台管理能力

## 建议的主线产品模型

> 以下内容已根据你的最新确认回填，后续实现默认以此为准。

### 1. 正式模式与调试模式

#### 正式模式

- [x] 每位普通用户只能正式提交并产出结果 `1` 次
- [x] 正式完成后，再次进入开始页时展示“已完成”状态与历史人格结果入口
- [x] 正式模式结果写入服务端，后续可再次查看结果，但不能再次正式作答

#### 调试模式

- [x] 仅 admin/debug 身份可见
- [x] 不占用正式唯一一次机会
- [x] 不覆盖正式人格结果
- [x] 可重复进入，用于排版和流程调试

### 2. 题目模型

- [x] 题目继续采用单选结构
- [x] 每个选项不表示“正确/错误”，而是给某个维度加 `1` 分
- [x] 题干与选项继续支持文本 / 图片 / 图文混合

### 3. 结果模型

- [x] 服务端维护固定的人格结果类型
- [x] 每道题的每个选项给 `E/I/S/N/T/F/J/P` 其中一个维度加 `1` 分
- [x] 全部题目提交后，由服务端统一计算最终人格结果
- [x] iOS 结果页展示人格名称、黑话标签、曲风对标、人设解读、可选配图

## 已确认的 EDMTI 测试规则

### 产品定位

- [x] `EDMTI` 是基于 MBTI 二创的恶搞向电音人格测试
- [x] 没有心理学依据，定位是“离谱但精准”的娱乐化测试
- [x] 对外文案可强调：`16 道题，约 3 分钟完成`

### 计分基础规则

- [x] 正式题库主链路以 `16` 道常规题为基础
- [x] 题目随机混排
- [x] 每题 `4` 个选项
- [x] 每个选项分别对应 `E/I/S/N/T/F/J/P` 中的一个维度
- [x] 选中某个选项后，对应维度 `+1`
- [x] 统计所有题目后，按四组对立维度计算人格：
  - [x] `E` vs `I`
  - [x] `S` vs `N`
  - [x] `T` vs `F`
  - [x] `J` vs `P`

### 维度判定规则

- [x] 某侧得分 `>= 9`，判定为该侧倾向
- [x] 某侧得分 `<= 8`，判定为对立侧倾向
- [x] 常规人格由 `EI + SN + TF + JP` 四组结果组合而成，共 `16` 种

### 隐藏人格触发规则

- [x] `DRUNK`：隐藏彩蛋题中选“必须喝到断片”直接触发
- [x] `HHHH`：四个维度得分均在 `7-9` 之间时触发
- [x] `CPDD`：隐藏彩蛋题中选“主打一个CPDD”直接触发
- [x] `PHOENIX`：第 `7` 题专属凤凰护短选项选中时直接触发

### 当前活跃人格数量与容量预留

- [x] 系统容量先按 `32` 种人格结果预留
- [x] 当前第一批业务规则实际启用的是：
  - [x] `16` 种常规人格
  - [x] `4` 种隐藏人格
- [x] 因此当前首批有效人格总数为 `20`
- [x] 其余结果位先作为保留扩展槽位

### 电音专属四维定义

- [x] `E/I 蹦迪社交轴`
  - [x] `E` = 外放社牛、爱热闹爱互动
  - [x] `I` = 内敛社恐、独处听歌、沉浸式自嗨
- [x] `S/N 听歌审美轴`
  - [x] `S` = 务实怀旧、偏爱经典热门、旋律好听优先
  - [x] `N` = 小众先锋、追新鲜实验、审美独特冷门
- [x] `T/F 情绪听歌轴`
  - [x] `T` = 理性解压、靠重鼓炸场宣泄情绪
  - [x] `F` = 感性治愈、靠旋律氛围感共情治愈
- [x] `J/P 听歌习惯轴`
  - [x] `J` = 规整自律、歌单整洁、听歌有规划
  - [x] `P` = 随性松弛、随缘听歌、随心所欲不拘束

## 正式灌题前必须先定的 4 个问题

### 1. 当前 `16 题 + 每题单轴 + 阈值 >= 9` 在数学上不成立

- [x] 当前实现支持 `E/I/S/N/T/F/J/P` 八轴加分
- [x] 但你提供的 16 道题里，单题只会给一个轴 `+1`
- [x] 这会导致总分虽然是 `16`，但每个对立维度拿到的有效样本数并不固定
- [x] 因此：
  - [x] `>= 9` 阈值几乎不可能成立
  - [x] `HHHH` 的“全部维度都在 7-9 分之间”也不成立
  - [x] 有些用户可能某一维度几乎没有被测到，就会被系统被动判去另一侧

### 2. 当前题面是“混合测维”，不适合直接做标准 MBTI 式四维判定

- [x] 例如某些题同时混合了 `T/F + S/N` 或 `E/I + J/P`
- [x] 用户选了一个选项，只会给其中一个轴加分
- [x] 这意味着该题并没有稳定测完两个维度，只是从多个维度里“抽中一个”
- [x] 如果硬按当前规则落库，最后四维结果会不稳定，也不够可解释

### 3. 即使改成 `16` 题平均分配四组维度，仍有高频平票风险

- [x] 如果 `E/I`、`S/N`、`T/F`、`J/P` 每组各 `4` 题
- [x] 且每题只是普通 `+1`
- [x] 那么每组维度很容易打成 `2:2`
- [x] 成熟做法通常会选以下其一：
  - [x] 提高每组题量，尽量用奇数题
  - [x] 保持 `4` 题，但用“强倾向/弱倾向”权重避免大量平票
  - [x] 或者额外定义稳定的 tie-break 规则

### 4. 现在服务端常规结果码与文案里的人格简称还没对齐

- [x] 当前服务端常规结果计算出来的是 `ESTJ / ENFP / INTP` 这类码
- [x] 但文案里的人格主标识是 `BOMB / SUNNY / GLIT` 这类简称
- [x] 因此正式灌题前需要先统一：
  - [x] 是让结果主码使用 `ESTJ`
  - [x] 还是改服务端，让 `ESTJ -> BOMB` 做一次映射

### 5. 第 2 题原稿存在重复选项，录入前要按修正版为准

- [x] 第 2 题原始文案里出现过一版重复选项
- [x] 正式灌题时应只保留去重后的版本

## 我建议的落地方案

### 推荐方案 A：保留 EDMTI 世界观，重整计分口径

- [ ] 保留 `16` 道正式题 + 固定第 `17` 题彩蛋题
- [ ] 保留 `16 常规人格 + 4 隐藏人格`
- [ ] 保留 `E/I/S/N/T/F/J/P` 四组世界观
- [ ] 但把常规人格判定从“绝对阈值 >= 9”改成“对立维度相对多数胜出”
- [ ] `HHHH` 改成“4 组对立维度都非常接近”的低差值判定，而不是 `7-9`

#### 这个方案下我建议再细化成两种子方案

- [ ] `A1 最稳妥`：重写题目映射，让每道题只测一组对立维度
- [ ] `A2 改动较小`：保留你现有题面文案，但允许部分题做“多轴加权”或重新分配到单一维度

### 备选方案 B：不再强求四维，直接按人格原型打分

- [ ] 每个选项不加 `E/I/S/N/T/F/J/P`
- [ ] 而是直接给 `BOMB / BOUN / ... / PURE` 这类人格原型加权
- [ ] 隐藏人格仍用直接触发
- [ ] 优点是最贴合你现有玩梗文案
- [ ] 缺点是“基于 MBTI 四维”的解释力会变弱
